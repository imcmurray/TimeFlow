# iPhone and iPad: hand-off for the Mac

This is the brief for whoever (human or Claude Code on the Mac) brings
TimeFlow to iOS. Everything that doesn't need a Mac is already done; what's
left needs Xcode and the Apple developer account.

## Already done (from Linux)

- `ios/` generated by Flutter 3.44 (UIScene lifecycle), bundle ID
  `com.rinserepeatlabs.timeflow` (same as Android), display name *TimeFlow*,
  deployment target **iOS 15**.
- `AppDelegate.swift`: notification-center delegate (so reminders show in the
  foreground and taps reach the app) and the plugin-registrant callback that
  lets **Done/Snooze** run in a background isolate when the app is closed.
  Follows flutter_local_notifications 22's own UIScene example.
- `Info.plist`: camera and photo-library usage strings, display name,
  `ITSAppUsesNonExemptEncryption = NO` (skips the export-compliance prompt),
  all orientations on iPad (required for iPad multitasking).
- App icons generated from the logo (`scripts/regenerate_ios_icons.sh`).
- `ios/Runner/PrivacyInfo.xcprivacy`: no tracking, no data collected,
  UserDefaults reason CA92.1. **Must be added to the Runner target in Xcode**
  (see step 2); until then it isn't bundled.
- CI builds iOS without signing on every PR (`ios` job in
  `.github/workflows/ci.yml`), so the project is known to compile.
- The Dart side already handles iOS: notification permission is requested on
  the first reminder (`NotificationService.requestPermission`), the reminder
  planner stays under iOS's 64-pending-notification cap (plans at most 60),
  share sheets pass `sharePositionOrigin` (needed for iPad popovers), and
  backups save through the system document picker.

## Steps on the Mac

1. **Tooling.** Xcode (latest), `flutter doctor` clean for iOS, Flutter
   **3.44.2** to match CI (`flutter --version`). Clone the repo and work on a
   branch from `main`.
2. **Open and sign.** `flutter pub get`, then open `ios/Runner.xcworkspace`.
   - Runner target → *Signing & Capabilities* → Team = your Apple developer
     team, automatic signing. Register the App ID
     `com.rinserepeatlabs.timeflow` if Xcode doesn't do it automatically.
   - Drag `ios/Runner/PrivacyInfo.xcprivacy` into the Runner group with
     *Target membership: Runner* checked.
   - No extra capabilities are needed: local notifications need none, and
     there's no push, iCloud or background mode.
3. **Run it.** `flutter run -d <iPhone simulator>`, then an iPad simulator,
   then your own iPhone (`flutter run --release -d <device>`).
4. **Test on a real device** (simulators don't deliver everything):
   - First reminder asks for notification permission; a reminder arrives with
     the app **closed**; tapping it opens the task; **Done** and **Snooze**
     work from the lock screen without opening the app.
   - Add a photo from the camera and from the library.
   - Share link / text / image (on iPad the share sheet must appear as a
     popover anchored to the screen, not crash).
   - Back up to Files and restore.
   - Timeline: long-press to create, long-press-drag to move, pinch zoom,
     swipe right/left on cards, the NOW chip, dark mode, Dynamic Type at the
     largest sizes, VoiceOver reads cards and offers *Mark done*/*Delete*.
   - iPad: portrait, landscape, Split View and Slide Over.
5. **App Store Connect.** Create the app (name *TimeFlow*, SKU `timeflow`,
   bundle ID above). Reuse the Play listing text in
   [store/listing.md](store/listing.md).
   - *App Privacy*: **Data Not Collected**.
   - Privacy policy: https://imcmurray.github.io/TimeFlow/privacy.html
   - Age rating: 4+. Category: Productivity.
   - Screenshots: 6.9" iPhone (1320×2868) and 13" iPad (2064×2752) are the
     required sizes. Fastest path: run the app in those simulators and use
     *File → Save Screen*, with the sample day from onboarding.
6. **First TestFlight build.** `flutter build ipa $(./scripts/build_flags.sh)`
   then upload `build/ios/ipa/*.ipa` with Xcode's Organizer or the
   Transporter app. Internal testers can install right away.
7. **Automate it (optional, recommended).** Create an App Store Connect API
   key (Users and Access → Integrations), add repository secrets
   `APP_STORE_CONNECT_KEY_ID`, `APP_STORE_CONNECT_ISSUER_ID`,
   `APP_STORE_CONNECT_KEY_P8`, plus a distribution certificate and profile
   (or fastlane match), and add an `ios` job to `release.yml` that runs
   `flutter build ipa` and uploads with `xcrun altool --upload-app` on
   tagged releases, mirroring the Android job.

## Things to watch for

- **Plugin pods / Swift Package Manager:** Flutter 3.44 may use SPM for
  plugins. If a plugin lacks SPM support, Flutter falls back to CocoaPods
  and needs `pod install` (it runs automatically on `flutter build`).
- **Notification timing:** iOS has no exact-alarm permission; scheduled
  notifications fire on time. The Android-only "allow on-time reminders"
  row won't appear on iOS.
- **Background isolate on iOS** only runs for action buttons, so it has the
  same limits as Android: it opens its own database and finishes quickly.
- **Version numbers:** CFBundleShortVersionString comes from `pubspec.yaml`
  and the build number from `scripts/build_flags.sh` (commit count), which
  satisfies App Store Connect's always-increasing build numbers.
- The plugin marketplace (branch `feature/marketplace`) adds nothing
  iOS-specific; if it's merged first, the steps above don't change.
